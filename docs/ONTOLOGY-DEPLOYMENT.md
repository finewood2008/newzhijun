# 本体雷达后端部署

当前客户端通过封闭的 `/api/ontology/*` 路由，向服务端解析出的私人角色 agent 发起请求；后端路径为 `/api/agents/{agent_id}/ontology`。账户所有者与 application 必须匹配，共享实例不可用，不接受管理员代替所有者确认。

## 安装边界

`backend-overlay/manifest.json` 固定本次核对的基线文件与依赖哈希。安装器先校验，拒绝覆盖不同版本，随后备份原文件并安装。适用于已含原知君本体模块的本地 WANX；不是任意 Octop 1.0.2b4 的通用安装器。

```sh
python3 tools/install-ontology-backend.py /path/to/wanx/packages/octop
```

若依赖不匹配，应在目标 WANX 源码内合并本补丁并测试，不要绕过校验直接覆盖 manager.py。备份写入 `verification/ontology-runtime-日期/`，不上传 Git。

随后使用该 WANX 原有进程管理方式重启，再重新启动知君 `npm start`。macOS 已安装的本机服务可以按其现有 launchd 标签重启；不要在其他部署上假定相同标签或端口。

## 数据与确认

- 各角色的 `zhijun/personal-ontology.json` 保存投影、本人确认状态、重要性、关联程度、历史与操作回执；它不复制原生记忆库。
- `fact_confirmations` 记录本人对特定原生 atom 版本的确认。promoted、提炼成功和重复出现次数都不等于本人确认。
- 模型可从当前角色可核对的本人原话准备待确认候选，不自动确认来源。本人明确自述须逐字引用，可单条形成候选；推断仍需至少两组独立经历。AI 回复、附件引文、停用/撤回来源不作为独立本人证据。
- “写一项”的确认按钮原子完成保存与纳入。候选卡的确认同时认可表述及展示的来源版本，无需先逐条确认事实；自动整理不能修改本人编辑过或已纳入的理解。
- 点的大小来自 importance，距离来自 affinity。两者独立于出现频率和模型置信度。
- 修改需要节点版本和幂等 request_id；来源变更、撤回、失效以及过期会排除可用上下文。停用保留历史，不删除原生事实。
- 所有本体文件仍处于用户控制的 WANX 工作区；本功能不试图抵抗拥有该目录写权限的本机管理员修改文件。

## 自动整理与状态

知君登录/角色切换调用受角色绑定保护的 `POST /api/ontology/prepare`，仅启用当前私人实例。WANX 现有后台生命周期每 60 秒检查已启用角色；记忆提炼完成后才有新事实可整理。角色正在对话或关闭记忆时暂停模型整理。任务按实例隔离、同角色防并发；来源未变化不重复调用模型，角色整理单次最多等待模型 120 秒；超时与内容校验失败分别说明，失败自动退避 5 分钟，用户可明确重试。

`preparation` 与确认记录共存于原本体 JSON。状态区显示已记录、待确认、已纳入、可用/排除来源、无新增、来源不足、模型失败或校验失败。来源页逐项解释排除原因；无新增候选不再伪报“整理好了”。

## 对话及资料

WANX 的 RoleOntologyMiddleware 在模型调用时选择当前角色有效本体，候选不进入正式上下文。与问题的匹配决定是否使用，屏幕上最多展示 15 个点不影响后台选择。

角色启用后，服务端根据当前真实用户轮及账户/实例绑定处理完整确认，例如“我确认我现在的核心是人工智能，这条可以进本体”。仅保存逐字表述，不由模型改写；写入与来源回执原子提交。只说“可以/这条进本体”、引用或假设不能确定目标时，不写入，提示核对候选或重述具体内容。不会回放历史对话自动补确认。失败回执不允许模型声称保存成功。

本轮轨迹位于角色工作区的 `zhijun/role-context/`，客户端可查看所参考的理解。排除项限定到下一用户轮及其后续工具调用；新一轮重新选取。停用则影响以后所有新上下文。

附件与知识库仍由原生解析、检索系统处理。本补丁给对话模型明确的两步解释规则：先忠实于资料作者与原意，再讨论与本人关联。它没有新增导入时自动生成独立报告的后台任务；真实模型遵循规则的质量仍需用代表性资料验证。

## 回滚

停止相关进程后，将安装器备份中的原 `.py` 文件恢复；删除目标升级前不存在的新模块（以备份清单为准，包括 `role_ontology_flow.py`），恢复上一版客户端构建，重启。保留各角色本体 JSON，可供再次升级恢复。不要删除个人记忆目录。

## 微信本人校验与对话刷新

新版知君私人实例（`zhijun-lan-user-<uid>[-<expert hash>]`、`zhijun-role-<uid>-<id>`）与旧 `zhijun` 应用均采用服务端扫码身份绑定。二维码 nonce 绑定当前账户和角色；微信返回的本人 ID 不由客户端提交。缺少本人 ID 的旧连接不启动处理，需重新扫码。通用通道创建与配置修改接口不能改写这些私人微信凭据。

私聊发送者、角色、机器人账户与当前有效连接必须匹配，其他联系人、群聊、已暂停/重绑的旧连接在会话、记忆、命令与推理之前拦截。同一微信机器人账户不能同时绑定两个角色，避免抢收及跨角色导入；换角色前先在 WANX 解除原连接。此限制不代表读取或导入整个微信历史。

客户端列表在页面可见时每 5 秒刷新，窗口重新获得焦点时立即刷新，不改变当前打开的会话。切换角色会取消原角色请求并丢弃迟到结果。这个改动不包含当前会话正文的实时推送。

已有本体补丁的服务可以仅安装微信相关三个文件，保留同期其他修改；安装器仍检查各文件基线并备份：

```sh
python3 tools/install-ontology-backend.py /path/to/wanx/packages/octop \
  --only api/routers/channels.py \
  --only infra/gateway/gateway.py \
  --only infra/gateway/channels/zhijun_weixin.py
```

本轮自动验证使用隔离测试身份和临时 SQLite：错误发送者不进入处理；本人原话经原生 MemoryService 捕获；明确本体声明经同角色写入，另一个角色为空。候选生成/确认由本体回归测试覆盖。它不代替手机微信真实收发、模型提炼质量和候选确认的端到端验收。不会自动清理或重新认定旧微信历史。

### 微信联系偏好与对话来源（2026-10-10）

- 微信连接新增四档主动程度：仅回复、偶尔关心（48–72小时）、适度关心（12–24小时）、更多陪伴（5–12小时），以及可联系时段。
- `/api/wechat/care` 在当前登录账户、专家、角色的所有权校验后调用该角色的原生 `proactive-care` API。PUT 仅接受预设档位和合法同日时间范围，不接受调用方指定 agent/user。
- 与“记忆 → 主动关心”共用原生角色设置，保存后原生 scheduler.reschedule 生效。打开页面只读，已有自定义频率原样显示。后台以账户时区安排、优先最近 IM 会话；微信需要已核验本人、启用并有会话。设置频率不是保证每次投递。
- 对话列表与当前标题显示原生 `channel_type` 来源，微信、客户端等分别标注；缺失来源显示“来源未知”，未知类型显示“其他渠道”，不猜测历史来源。
- 本机验收：微信真实会话及客户端历史均有对应标签；设置能够读取现有角色配置。保存与权限隔离通过自动化测试；没有为了验收提高真实账户联系频率或主动向微信发送测试消息。
