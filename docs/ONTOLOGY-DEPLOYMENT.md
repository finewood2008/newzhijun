# 本体雷达后端部署

当前客户端通过封闭的 `/api/ontology/*` 路由，向服务端解析出的私人角色 agent 发起请求；后端路径为 `/api/agents/{agent_id}/ontology`。账户所有者与 application 必须匹配，共享实例不可用，不接受管理员代替所有者确认。

## 安装边界

`backend-overlay/manifest.json` 固定本次核对的基线文件与依赖哈希。安装器先校验，拒绝覆盖不同版本，随后备份原文件并安装。适用于已含原知君本体模块的本地 WANX；不是任意 Octop 1.0.2b4 的通用安装器。

```sh
python3 tools/install-ontology-backend.py /path/to/wanx/packages/octop
```

若依赖不匹配，应在目标 WANX 源码内合并本补丁并测试，不要绕过校验直接覆盖 manager.py。备份写入 `verification/ontology-runtime-日期/`，不上传 Git。

随后使用该 WANX 原有进程管理方式重启，再重新启动知君 `npm start`。macOS 已安装的本机服务可以按其现有 launchd 标签重启；不要在其他部署上假定相同标签或端口。

## 数据与确认

- 各角色的 `zhijun/personal-ontology.json` 保存投影、本人确认状态、重要性、关联程度、历史与操作回执；它不复制原生记忆库。
- `fact_confirmations` 记录本人对特定原生 atom 版本的确认。promoted、提炼成功和重复出现次数都不等于本人确认。
- 模型整理只读取当前角色有本人原文、且已确认版本的记忆来源，至少两段独立经历。未达到时返回 insufficient，不制造完整画像。
- 亲自写下的理解先保存为候选，再明确确认纳入。自动整理不能修改本人编辑过或已纳入的理解。
- 点的大小来自 importance，距离来自 affinity。两者独立于出现频率和模型置信度。
- 修改需要节点版本和幂等 request_id；来源变更、撤回、失效以及过期会排除可用上下文。停用保留历史，不删除原生事实。
- 所有本体文件仍处于用户控制的 WANX 工作区；本功能不试图抵抗拥有该目录写权限的本机管理员修改文件。

## 对话及资料

WANX 的 RoleOntologyMiddleware 在模型调用时选择当前角色有效本体，候选不进入正式上下文。与问题的匹配决定是否使用，屏幕上最多展示 15 个点不影响后台选择。

本轮轨迹位于角色工作区的 `zhijun/role-context/`，客户端可查看所参考的理解。排除项限定到下一用户轮及其后续工具调用；新一轮重新选取。停用则影响以后所有新上下文。

附件与知识库仍由原生解析、检索系统处理。本补丁给对话模型明确的两步解释规则：先忠实于资料作者与原意，再讨论与本人关联。它没有新增导入时自动生成独立报告的后台任务；真实模型遵循规则的质量仍需用代表性资料验证。

## 回滚

停止相关进程后，将安装器备份中的原 `.py` 文件恢复；删除本次新增的两个 `role_ontology.py` 文件，恢复上一版客户端构建，重启。保留各角色本体 JSON，可供再次升级恢复。不要删除个人记忆目录。
