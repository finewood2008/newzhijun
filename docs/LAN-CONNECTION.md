# 局域网发现与 WANX 登录

“连接服务”仅在登录前的页面右下角显示；进入知君后隐藏入口和连接面板。搜索和手动输入地址收在连接面板内，主登录表单只显示账号、密码和登录按钮。内置 slider 仅为前端交互，WANX 不校验令牌，知君已取消这一步；其他 WANX 如启用真正的第三方验证码，仍按其要求验证。

1. 搜索列出局域网中广播 `_wanx._tcp` 的服务，并检查健康与登录接口。已有配置的 WANX 也作为候选地址检查。
2. 点击“选择并登录”会退出当前会话，显示目标服务名称、地址并要求重新登录。其他同源标签页同步刷新。
3. 登录后自动检索万象“我的专家”中的知君。只有一个可用结果时直接进入；有多个时显示小弹窗，选择随当前加密会话保存。“连接服务”只负责选择服务地址。共享来源专家必须映射到当前账户的私人实例，不能直接作为个人记忆空间。
4. 未安装广播扩展的 WANX 可以手动输入 LAN IPv4 origin，例如 `http://192.168.1.20:8088`。不接受凭据、路径、查询参数、公网 IP 或云元数据地址。

## 网络与身份

Windows 0.4.2 的搜索在桌面主进程执行，范围是**Windows 客户端所在局域网**；无需先连接 Mac 的知君网关。客户端直接连接所选 WANX 的登录、专家和数据接口，复用 Web 版的权限与角色隔离逻辑。Web 部署的搜索仍由知君 Node 服务执行，范围是运行该服务的电脑所在局域网。浏览器不会直接广播。跨网段、多播被阻止、VPN 或客户端隔离均可能影响发现，手动地址仍可用。

macOS 优先调用系统 Bonjour 查询，再验证返回的私网 IPv4 服务；其他系统使用 `bonjour-service`。发现请求不携带账户或令牌。广播内容和 HTTP 身份接口不是密码学上的设备认证；HTTPS 使用系统证书验证，不忽略证书错误。HTTP 明文登录只适合用户信任的局域网。

连接按端点隔离：每个后端有独立会话、实例绑定和角色目录。切换不修改已经发出的请求的目标。旧会话和 WebSocket 被撤销，客户端取消角色请求并重新加载。更换 IP 会被视为一个新端点，需要重新登录并重新匹配知君，不会根据可伪造的广播 ID 自动迁移令牌。

## WANX 端安装

当前本机 WANX 已安装。其他 WANX 需要合并 `backend-overlay/lan/octop/` 的三份文件：

- `api/lan_discovery.py`：公开最小服务描述，启动和停止 mDNS 广播。
- `api/app.py`：挂载 `/.well-known/wanx`，不改变现有登录鉴权。
- `launch.py`：把实际监听地址、端口和 TLS 状态传给广播模块。

在 WANX 的 Python 环境安装 `backend-overlay/lan/requirements.txt`，然后执行 `tools/install-lan-backend.py /实际/octop/目录`。安装器仅接受 manifest 对应的本地基线，先备份再安装；其他版本必须合并，不能覆盖。重启 WANX 生效。设置环境变量 `WANX_LAN_DISCOVERY=0` 可关闭广播；仅监听 localhost 时不广播。发现失败不阻止 WANX 正常启动。

## 本轮验证

- 已通过真实 Bonjour 发现本地 WANX，测试未提供种子地址；实际网页搜索结果可选择并回到目标登录页。
- 自动化验证旧令牌不会跨后端发送、切换撤销会话、拒绝共享或他人实例、手动地址错误保留输入、跨站请求拒绝、桌面会话失效后仍保留后端选择。
- 登录成功、失败与实例绑定由隔离的模拟服务测试覆盖；真实登录验证码留给用户操作。未在第二台物理盒子或 Windows 实机验收。
- Windows 0.4.1 安装包包含这一轮新的前端入口；0.4.0 安装包不包含。桌面连接的知君服务端也需更新到相应源码，单独替换 EXE 不会更新服务器。

以上 0.4.1 保留了旧桌面网关启动方式，已在 0.4.2 移除。0.4.2 启动直接显示高山流水登录页；“家里的知君”“在外也能连接”和配对码入口均不打包。首次选择服务前不会向默认地址发起请求，选择后保留端点；会话通过 Windows 系统安全存储加密。WANX 本身仍需具备客户端所用接口，本体补丁与可选广播扩展的要求不变。


## 选择知君专家

使用万象“专家 → 我的专家”背后的 `/api/agents?scope=mine` 列表，按当前登录账户的权限检索名称包含“知君”的专家。排除团队、客户端自动创建的私人实例和个人／工作角色实例；不读取内置专家模板或专家市场。

首次进入只有一个可用知君时自动连接；多个可用知君一律显示小弹窗，不按名称排名替用户决定。已有选择随加密会话保存，在仍可访问时继续使用。进入后不再显示专家选择入口，“连接服务”只负责搜索和切换万象。没有匹配结果或权限不足时显示原因与重试，不回落到其他专家。

来源专家与记忆实例分别记录。已有管理员配置的私人实例和角色继续使用。首次使用本人拥有的共享专家，或已提供行为模板的共享专家时，自动创建当前账户专属的私人实例；只复用已配置的行为说明，或本人专家的 AGENTS.md，不复制记忆、画像、聊天、知识库和工作区内容。未提供行为模板的其他用户共享专家仍不可直接绑定。

角色创建不再依赖预先写入的账户名单。已连接的专家提供行为与模型，新角色使用独立实例、虚拟文件系统、记忆和私人知识库，工作区由万象所在服务器分配。角色按后端、账户和来源实例隔离，旧账户的角色不会迁到新账户。客户端取消旧请求并重建页面，多标签页同步刷新；服务端校验实例作用范围，阻止旧页面请求落到新实例。

## 角色修复验收（2026-10-10）

89 项服务端测试、47 项 UI 测试及生产构建通过。当前 28730 客户端实际连接万象的知君专家，为当前账户准备私人空间并创建“工作”角色；个人与工作各自的对话 WebSocket 返回 ready，对话、记忆统计和知识库接口返回 200，知识库与工作区不同。跨角色知识库访问返回 403，他人角色访问返回 404。未发送测试对话，未验证真实模型输出；旧账户与来源专家内的历史数据保留。
