# 知君 · 本体雷达设计

状态：产品与交互设计，尚未接入当前运行客户端。交互稿中的人物理解、原话、数量均为示例。用户已选择：每个角色独立构建本体，继续保持记忆隔离。

## 1. 产品定义

个人本体是一组有来源、由本人确认、带有适用情境、可以修正和撤回的自我理解，以及这些理解之间的关系。它回答“在这个角色里，我如何看待自己、重视什么、如何选择、希望走向哪里、希望如何被理解”。

它作为知君理解资料、理解对话和辅助判断的共同依据。它为用户提供可回看的北极星与个人说明书，最终选择仍由用户决定。过去的本体不能否定用户现在明确表达的变化，也不自动授权代替用户行动。

本次聚焦“用户画像”内的雷达与个人本体，不改动其他记忆视图。画像内保留“本体雷达 / 记忆资料”两个视图。主雷达承载经本人确认的核心理解；人、项目、事件、原始事实作为可展开的关联线索与证据保留在记忆资料中。

## 3. 雷达的视觉含义

| 视觉变量 | 代表什么 | 规则 |
| --- | --- | --- |
| 圆点面积 | 对用户的重要程度 | 沿用一般 / 重要 / 非常重要三个等级；参考半径 9 / 14 / 18 |
| 离中心距离 | 与当前角色里的自我关联程度 | 核心 / 密切 / 相关 / 间接 / 外围；越贴近自己越靠近中心 |
| 所处方向 | 本体类别 | 固定五类；布局变化不改变内容的类别 |
| 节点文字与标识 | 本人确认、待重新核对或已停用 | 默认雷达只展示当前有效的已确认节点 |
| 选中后的连线 | 节点间有证据支持的关系 | 支持、平衡、改变；只在选中后展开，关系推断也需核对 |

三种量保持独立：重要程度不是置信度，自我关联程度不是当前话题相关度，出现次数不是本人认可程度。负面经历可能很重要且很贴近自己；不能被解释成能力分数或人格优劣。

关联程度的语义：核心＝持续影响这个角色的自我定位；密切＝多数相关情境都会涉及；相关＝特定领域适用；间接＝作为背景有帮助；外围＝较少直接影响当前自我理解。AI 可建议初值，并说明依据；由本人确认，后续用户调整优先。

布局参考：中心保留 80 单位不放节点，外圈半径 220，五档半径为 88 / 121 / 154 / 187 / 220。同类节点用稳定 ID 分配角度，碰撞调整优先沿圆周移动，不悄悄修改关联程度。屏幕显示尺寸只作呈现，不写回权重。

首页默认展示最多 15 个节点，优先用户设定的重要程度和关联程度；其余通过分类、搜索和同步列表查看，显示“已展示 / 总数”。不将未展示节点排除出检索。空类别保持空白，不为凑满图形生成理解。首版不使用自由拖拽改变权重，点击后用清晰的等级控件调整；键盘和列表可以完成同样操作。

## 4. 从记忆到本体：事实与自我理解分别确认

原始对话 / 导入资料 → 原生记忆事实与来源 → 本体候选 → 本人核对内容及范围 → 有效本体 → 对话与资料的理解依据。

- 重点使用本人确认过的事实、本人主动声明，以及能够追溯到独立事件的记忆。低置信推断、第三方立场、过期材料可以作为待核对线索，不能自动进入核心本体。
- “事实正确”与“对我的解释正确”分开。例如“我拒绝了一次高收益合作”不直接推出“我不在乎收入”。候选应显示原话、推导出的理解、例外及为何提出。
- 核对界面提供“仅确认事实”和“确认这项理解并纳入本体”。后者确认具体表述、重要程度、关联程度、适用情境与当前角色。只确认事实时保留资料，不新增核心点。
- 一次拒绝、一次情绪或单篇文章不自动固化为人格结论。用户明确自我声明可以直接发起确认，不强制要求多次出现。
- 同一文件的重复上传和同一对话的重复引用不能计作多份独立证据。候选相似时提出合并建议，保留原始 ID、范围、例外和来源，不覆盖本人已确认或编辑的内容。
- 新信息与现有本体冲突时生成“变化待核对”；保留旧版与新证据，让用户选择纠正原理解、限定范围或记录“我发生了变化”。AI 不直接覆盖确认版本。

## 5. 点选与直接修改

桌面为左侧雷达、右侧编辑面板；手机上下排列，点击后可展开节点详情。右侧按“表述 → 情境与例外 → 两种权重 → 依据与来源 → 保存 → 修改记录”组织，依据默认展开。

- 节点点选后可直接修改文字、适用条件与例外；类别可通过显式分类操作更改，不能根据拖动方向猜测。
- 两个等级控件分别调整大小和距离。调整时图中即时预览，以虚线圈及“预览中”说明，保存前不影响系统理解。
- 保存执行版本检查，成功后重新读取并核实；并发修改要求重新核对差异。失败保留草稿，不能仅凭动画显示已保存。节点切换或角色切换时保留或明确放弃未保存草稿。
- “纠正原理解”保留原来源与更正说明；“我发生了变化”记录生效时间与历史，不把过去的事实改成从未发生。
- “停止使用”立即退出后续有效本体与上下文引用，保留历史和依据，可恢复。撤回本体与删除原始记忆是不同操作。
- 来源被删除、撤回或无法验证时，标为“依据失效／待核对”，不再作为证据充分的核心理解静默使用。用户可以重新明确声明，形成新的本人声明依据。
- 用户只修改重要程度时不生成新事实；修改自我表述则产生新版本和本人编辑记录。不得让下一轮自动提炼将它恢复成旧表述。

交互稿已演示：点选、文字与范围编辑、大小和距离实时预览、保存、停止／恢复使用、候选确认、资料追溯、角色切换、空状态、修改记录。示例保存只在页面内存中生效，刷新恢复。

## 6. 如何成为北极星与个人说明书

### 资料导入

第一遍提取忠实于材料的人物、时间、事件、论点和来源；第二遍才使用当前角色的有效本体解释“与我有什么关系”。输出原文事实、与本体相关的线索、新问题、需要核对的矛盾。原始解析不因本体而改写，也不把第三方文字归到用户名下。

例如用户已确认“重视长期可信”，导入合作文件时，知君可以优先提醒承诺、履约条件及其与用户取舍的关系；仍需展示原文依据，不能断言用户一定会拒绝该合作。

### 对话理解

先识别本轮问题、人物和情境，在当前角色内检索适用的本体，再结合相关记忆与资料形成回答。先做角色权限、有效状态、适用范围过滤，再按话题相关性选择；用户的重要程度与关联程度只用于相关项的优先级，不让“大点”每次都进入提示。

个人说明书由有效本体生成五类可追溯的简短说明：我如何定义自己、我重视什么、我如何取舍、我希望走向哪里、请如何与我相处。它是同一套本体的阅读视图，不另存一份不可追溯的人设摘要。

回答按需提供“本次参考了哪些理解”，可展开节点及来源；用户可选择“这次不适用”或“以后停止使用”。没有适用本体时根据本轮表达回答或澄清，不能强行套用画像。新表达与旧本体冲突时，先理解本轮意图，再邀请用户核对是否发生变化。

首版用于理解和建议，不触发代发消息、替用户决定或自动执行。当前明确指令和有效例外优先于长期偏好。用户可选择本次不使用本体，核心记忆仍然保留。

## 7. 角色、数据与实现边界

每个角色单独拥有事实来源、候选、本体节点、权重、关系、历史和上下文缓存。请求仍由服务端根据当前账户与角色绑定解析到私人 WANX agent，不接受客户端任意指定 agent。个人与工作之间不自动复制节点或共享所谓共同人格。

当前 `ProfileRadar.tsx` 只是四类原生记忆摘要的只读投影，最多每类 12 条，位置由 ID 哈希分布，不表达重要程度或关联程度。现有 `AtomItem` 提供重要程度、置信度、废弃信息等，但不包含完整的本人确认版本及本体准入记录；不能把 `promoted` 等同于本人确认。

旧知君的 `/zhijun/ontology` 与核心准入机制可以作为语义与实现参考。当前轻客户端通过另一套私人 agent 绑定访问原生 WANX，不应直接拷贝旧 API 地址，假定它们适用当前角色。

实现需要在 WANX 侧承载角色范围内的本体派生与确认能力，继续以原生记忆作为事实源；客户端负责可视化与编辑请求，不另建事实库，不在 localStorage 中保存正式本体，不把整张图一次性写进固定提示词。

最小后端能力合同（拟新增，尚未接入）：读取当前角色本体、从新记忆生成候选、确认纳入、带预期版本的编辑／权重／停用／恢复、读取来源与历史、为当前对话或导入任务选择有效上下文。写入要求幂等请求 ID、预期版本、来源版本和审计信息；冲突返回可重新核对的状态。原始事实确认与核心理解准入必须独立记录。

节点至少保存：稳定 ID、角色范围、类别、表述、情境与例外、时间范围、重要程度、本人设定关联程度、状态、来源引用、本人确认的版本／时间／身份、当前版本与历史。模型生成置信度独立保留，不能复用两个视觉权重。关系同样携带来源及确认状态。

更新、停用、角色切换及来源撤回后，失效对应范围的派生图与检索缓存；后续回答按新版本取用。已经展示的回答保留其当时引用记录，不伪装成使用了更新后的理解。

## 8. 分步落地与验收

1. 先完成本体准入、来源与版本能力；以本次设计稿替换用户画像雷达，并接通节点编辑。读图与列表一致，保存失败和并发冲突可恢复。
2. 接通本体上下文选择，先用于对话理解，显示本轮参考节点；确认它影响的是相关理解，而不是每轮重复同一人设。
3. 接入资料解析的第二遍个人相关性分析，提供矛盾与候选核对；原始资料解析结果保持可核对。

验收场景：未确认候选不入核心；已确认事实不会自动升级为价值判断；重要程度和距离独立变化；用户编辑后自动提炼不会覆盖；历史与依据可追溯；停用节点不再参与下一轮；来源撤回可联动；个人／工作不可串读；同一资料重复导入不会伪造多份证据；新表达与旧本体不一致时允许用户改变；资料第三方观点不被当成本人立场。

质量验收使用用户认可的一组固定记忆、导入资料和真实问题，比较启用／不启用本体时的人物归属、范围判断、来源准确性、理解偏差与用户纠正次数。目标是减少误解，不以聊天时长或本体节点数量作为成功指标。
